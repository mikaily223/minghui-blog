# 第 1 章　为什么需要 Transformer

**学习目标**

- 理解序列数据为什么特殊,以及 RNN 如何处理它。
- 说清 RNN 的两个致命痛点。
- 理解 LSTM 缓解了什么、没解决什么,从而明白 Transformer 的动机。

本章先不碰 Transformer 本身,而是认识它的前辈 RNN 和 LSTM,体会它们的痛点。理解了痛点,你才会明白 Transformer 那些设计为什么"非这样不可"。

## 1.1　序列数据与顺序的重要性

语言是一种序列数据:词一个接一个出现,而且**顺序至关重要**。"狗咬人"和"人咬狗"用词完全相同,意思却相反。此外,句子长度还不固定。因此处理语言的模型必须做到两件事:既理解每个词,又能把前面读过的内容"记在心里",用来理解后面的词。

## 1.2　RNN:靠一个会更新的"记忆"

RNN 的核心想法很符合直觉,就像你读句子的过程:从左到右一个词一个词地读,脑中始终维护着一份"到目前为止的理解"。每读到一个新词,就用"新词 + 脑中已有的理解"更新出一份新的理解。

这份"脑中的理解"在 RNN 里叫**隐藏状态(hidden state)**,本质是一个向量。它的更新其实就是一个层,同时接收两样输入:当前这个词的向量,和上一步传来的隐藏状态。

```
词₁ → [RNN] → h₁
              ↓（把记忆传给下一步）
词₂ → [RNN] → h₂
              ↓
词₃ → [RNN] → h₃ → ……
```

每一步的 `h` 都浓缩了"从开头到现在"读过的所有信息,再传给下一步。这种"把状态一环扣一环传下去"的结构,就叫**循环(Recurrent)**。这个设计很优雅,但它有两个致命痛点。

## 1.3　两大致命痛点

**痛点一 · 长距离依赖被稀释**。看这句话:"我在**法国**长大,小时候搬过好几次家……所以我能说一口流利的 ____。"要正确填出"法语",模型必须记得开头的"法国"。但在 RNN 里,这条信息要从第一个词经过几十个隐藏状态一环环传到结尾——就像一句话在很多人之间口耳相传,传到最后早就走样或丢失了。距离越远,信息被稀释得越厉害。在训练上,这表现为有名的"梯度消失"问题。

**痛点二 · 无法并行**。注意上面那张图:`h₂` 必须等 `h₁` 算完才能算,`h₃` 又必须等 `h₂`。每一步都依赖上一步,所以只能一个词一个词地排队计算,无法同时进行。这意味着 RNN 用不上现代 GPU"一次算一大批"的能力,句子越长,训练越慢。

## 1.4　LSTM:打了补丁,但没断根

为了缓解"记不住远处信息"的问题,人们改进出了 LSTM。它在 RNN 的基础上加了一条专门的"记忆传送带",以及几个叫**门(gate)**的开关。

门的本质是一组 0 到 1 之间的"阀门"值——0 表示完全关闭、不让信息通过,1 表示完全放行。这些 0 到 1 的值由 **sigmoid** 函数把任意数挤压而来,再用"对应位置相乘"去控制信息通过多少。三个门各管一摊:遗忘门决定抹掉哪些旧记忆,输入门决定写入多少新信息,输出门决定这一步对外输出什么。

> **关键**:门"该记什么、忘什么"不是人手写死的规则,而是在训练中通过梯度下降**学出来**的。

但请记住:LSTM 只**缓解了痛点一(长距离)**,对**痛点二(并行)无能为力**——它骨子里仍是"一个词一个词顺序处理"的循环结构。

## 1.5　Transformer 的破局思路

到这里你已能看出问题的核心:麻烦全都来自"循环"——信息非得沿着一条长链一环环传递。Transformer 做了一个大胆的决定:**干脆把循环彻底扔掉**。它让句子里的每个词,都能"一步直达"地去看其他所有词,并自己判断该重点关注谁。

这一招同时干掉了两个痛点:第一个词和第一百个词可以**直接**建立联系,不再被中间环节稀释(解决长距离);而"所有词同时互相查看"的操作本质是几次大矩阵乘法,**天然可以并行**(解决速度)。实现这个想法的机制,就叫**注意力(Attention)**,也是下一章的主角。

## 本章小结

RNN 用隐藏状态顺序处理序列,但受困于长距离稀释与无法并行;LSTM 用门控缓解了前者,却没解决后者。Transformer 抛弃循环、改用注意力,一举解决两个痛点。

## 练习

3. LSTM 解决了两个痛点中的哪一个?另一个呢?
